# AGENT

Astarots is a Python project bootstrapped with `uv`, currently at version `0.1.0` on Python `>=3.12`. The codebase follows a modular per-function layout where every feature lives in its own subpackage rather than being scattered across type-based directories like `models/` or `services/`. This keeps related code close and makes it straightforward to add, modify, or remove features without hunting across the tree.

The entry point sits at `main.py` with a minimal `main()` function called under `__name__ == "__main__"`. Project metadata and dependency declarations live in `pyproject.toml`, managed exclusively through `uv add` and `uv remove` so the lockfile stays in sync. Runtime and tooling versions are tracked in [doch/.initial/Depedensi/README.md](doch/.initial/Depedensi/README.md) — currently Python 3.14.6 with uv 0.11.32 and zero application dependencies.

Application source code belongs under `devil/`, organized into subpackages named after the function they serve. Shared infrastructure that spans multiple features — configuration, logging, base exceptions, common types — lives in `devil/core/`. Every subpackage exposes its public API through `__init__.py` so callers import from the package rather than reaching into internal modules. The expected internal structure of a feature module is documented in the project structure reference at [doch/.initial/Project stukture/README.md](doch/.initial/Project%20stukture/README.md).

Tests mirror the `devil/` tree one-to-one under `tests/`, with a shared `conftest.py` for fixtures that apply across the suite. Every source file under `devil/` maps directly to a corresponding test file under `tests/` — `devil/user/models.py` is tested by `tests/user/test_models.py`, and so on. This mirroring makes the test location predictable and eliminates the question of where a new test should go.

Documentation lives in `doch/` with a bootstrapping layer under `doch/.initial/` that captures decisions and references made during project setup. These initial docs are not part of the shipped documentation — they exist to ground future contributors in the choices that shaped the repository. The full directory layout and architectural rationale are in the project structure doc linked above; the dependency table with version numbers and links is at the dependencies doc.
